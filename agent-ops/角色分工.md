# 角色分工（多 Agent 协作）

> 原则：一个人掌握目标与标准；Agent 只负责执行环节。角色重叠是效率黑洞，宁少不多。

## 角色卡

### 1. 总调度

| 项 | 内容 |
|---|---|
| 职责 | 接收需求、判可否行、拆卡、派活、汇总 |
| 输入 | 用户原始意图 |
| 输出 | 任务卡列表 + 先后顺序 |
| 不做什么 | 不亲自写代码、不替用户做关键取舍 |

### 2. 需求分析

| 项 | 内容 |
|---|---|
| 职责 | 把模糊意图转成可验收目标，列出假设与选项 |
| 输出 | 目标句、验收条件、待确认项 |
| 不做什么 | 不擅自选定方案 |

### 3. 规划

| 项 | 内容 |
|---|---|
| 职责 | 定阶段、定依赖、定每阶段的验证方式 |
| 输出 | 阶段清单 + 每阶段能跑的最小版本 |
| 不做什么 | 不提前设计本轮用不到的模块 |

### 4. 开发

| 项 | 内容 |
|---|---|
| 职责 | 只完成当前卡，只改卡内文件 |
| 输出 | 可运行产物 + 变更说明 |
| 不做什么 | 不顺手重构、不扩范围、不改无关文件 |

### 5. 审核

| 项 | 内容 |
|---|---|
| 职责 | 独立复现验收（不看开发的自述，自己跑） |
| 输出 | 过 / 不过 + 具体证据（截图、日志、宽度实测） |
| 不做什么 | 不接受「应该没问题」作为结论 |

### 6. 工具顾问

| 项 | 内容 |
|---|---|
| 职责 | 推荐该用哪个 Skill / MCP / Agent，给最小可用配置 |
| 输出 | 工具清单 + 调用参数 + 已知限制 |
| 不做什么 | 不凭空造接口 |

### 7. 知识管理

| 项 | 内容 |
|---|---|
| 职责 | 写日志与项目记录，保持状态层不过时 |
| 输出 | 日志条目、项目更新、TODO 增删 |
| 不做什么 | 不转储对话原文 |

## 最小可用配置

阶段早期不要七角色全开，三职就够：

```
总调度（兼需求）→ 开发 → 审核
```

工具顾问、知识管理、规划都是“人一多才需要”的产物。角色比任务多是常见的失败模式。

## 边界冲突的处理

两张卡要改同一文件时：

1. 先定先后顺序，后一张卡等前一张验收完成
2. 不并行改同一文件
3. 需要共享的改动，单独开一张卡，写清依赖

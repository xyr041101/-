# 验收与回滚

> 目的：把“Agent 说完成了”和“真的完成了”分开。

## 验收的三个层次

| 层 | 验什么 | 怎么验 |
|---|---|---|
| 能跑 | 进程/页面/脚本能不能启动 | 自己命令行跑一次或浏览器打开 |
| 对不对 | 是否符合目标与约束 | 按验收条件逐条勾，不看自述 |
| 影响面 | 有没有弄坏其他东西 | 检查相邻文件、相邻页面、相邻模块 |

三层都过才算完。只过第一层就交付，是很常见的坑。

## 审核 Agent 的自检要求

- 必须自己重跑一遍，不复用开发 Agent 的输出截图
- 每条验收标准单独给证据（命令输出 / 截图 / 宽高数值）
- 没验的项必须写出来，不能空着

## 回滚检查单

- [ ] 改动前有备份，位置明确
- [ ] 回滚步骤写在任务卡里，不是“我记得怎么改”
- [ ] 回滚后能恢复到改动前的可运行状态
- [ ] 数据库/配置类改动有导出快照
- [ ] 部署类改动能一键回上一个版本

## 什么时候必须停下来问

- 需要改共享文件或公共配置
- 需要删文件、删分支、改权限
- 发现需求与现状冲突
- 连续两次验证失败
- 需要新增依赖

这五种情况不要自行决定。

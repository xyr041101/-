# 任务卡模板

> 一张卡 = 一个可交付单元。卡内只写这张卡的事；范围变大就开新卡，不在原卡上无限追加。
> 背景：多 Agent 协作里最常见的失控不是能力不够，而是任务边界含糊。

## 基本信息

- 卡号：`T-YYYYMMDD-NN`
- 负责 Agent：
- 关联项目：
- 状态：待启动 / 进行中 / 待验收 / 已验收 / 已回滚

## 目标（一句话，必须可验收）

> 例：把官网首页第 3 屏换成真实三系统界面拼图，1440 与 390 宽下不横向滚动。

合格的目标句 = 动作 + 对象 + 验收条件。做不到就拆卡。

## 验收标准

- [ ] 能在真实环境打开或运行，不是只存在于文档
- [ ] 指定宽度下无溢出、无错位
- [ ] 与既有 token / 命名 / 结构一致
- [ ] 有明确回滚方式
- [ ] 不遗留未清理的临时文件、调试代码

## 交接给审核 Agent 时贴这几句

```
本卡已完成，交付物在 <路径/链接>。
我验证了：<命令或截图>
我没验证的：<空白项>
已知风险：<...>
```

明确区分「我验证过的」和「我认为应该没问题」的。
